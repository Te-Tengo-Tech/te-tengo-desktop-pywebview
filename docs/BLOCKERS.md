# Blockers

Things the agent cannot decide or get by itself. Work continues with fakes; the team resolves each item.

| Item | What is needed | Owner | Status |
|---|---|---|---|
| UI copy after edge processing | The prototype (screens 01, 06) says «Enviando video» and «Video cifrado». With ADR 0007 the agent sends events and clips, not video. Until the team updates the prototype, the copy is used verbatim from `core.js` and kept in one module (`te_tengo_captura/estado.py`; the in-window notices of `proto.js` live in `ui/web/app.js`) so it is easy to change. | Team | Open |
| Live view transport | Decided on 2026-10-07 by the project owner: H.264 published to MediaMTX, controlled over the WebSocket `/api/agente/transmision` (`docs/AGENT_CONTRACT.md`, "Live view"). T18 is done. | Team | Resolved |
| «En vivo» indicator | The prototype (`core.js`) has no copy nor state for «someone is watching the live view», so the window and the tray show nothing while the agent publishes (the log records it). If the team wants the household to see it, the prototype needs the copy and the icon. | Team | Open |
| Tray menu texts | The prototype shows the tray icon and its notifications but not the right-click menu. «Abrir Te Tengo Captura» and «Salir» are placeholders until the team confirms them. | Team | Open |
| Hardware checks | Webcam, display, tray and Windows packaging cannot be tested in the cloud. See the local test checklist in `docs/WORK_PLAN.md`. | Team (local) | Open |
| Dataset validation | `make validar` downloads URFD and CAUCAFall from hosts outside the cloud allow-list. Any change to the detection logic must be validated locally. | Team (local) | Open |
| Windows code signing | Without a certificate, Windows SmartScreen warns on first run. Acceptable for the pilot; record the decision. | Team | Open |
| macOS camera permission text | macOS shows the app's `NSCameraUsageDescription` when it asks for camera access. Neither the prototype (`core.js`) nor the backlog has copy for it, so the bundle uses the minimal factual sentence «Te Tengo Captura usa la webcam para detectar caídas.» (`packaging/te-tengo-captura.spec`). The team should confirm or replace it. | Team | Open |
| macOS notarization | Without a Developer ID certificate (Apple Developer Program, US$99 per year) the `.dmg` is only ad-hoc signed and every tester has to allow it in Privacy & Security once (README, «Testing on macOS»). Fine for testing; households need `ENABLE_MAC_NOTARIZE` and its secrets (`docs/RELEASES.md`). | Team | Open |
| macOS: two FFmpeg builds in one process | On macOS, PyAV and OpenCV (pulled in by MediaPipe) each bundle their own `libavdevice`, and the Objective-C runtime warns that `AVFFrameReceiver` and `AVFAudioReceiver` are implemented twice. It happens the same way when running from source, and `--autoprueba` passes, but the webcam path on macOS needs a check on real hardware (local test checklist). | Team (local) | Open |
| Rejected installation credential | The prototype has no screen or copy for `401 CREDENCIAL_INVALIDA`. The agent logs it, keeps retrying and shows the «Sin internet» state (04), which tells the family to wait and the window note tells them to call the team. A specific copy is needed if the team wants one. | Team | Open |
| Video codec license | PyAV's wheels bundle `libx264` (GPL-2.0-or-later), used to encode the clips (ADR 0008) and the live view. Fine for the pilot; review before wider distribution or switch to an LGPL build with OpenH264. | Team | Open |
| Internal error state | The prototype has no screen for an unexpected error in the capture loop. While the loop restarts after an error, the agent shows «Webcam desconectada» (05) and reports `webcamConectada: false`, because the effect is the same (no images are processed). A specific copy is needed if the team wants one. | Team | Open |
